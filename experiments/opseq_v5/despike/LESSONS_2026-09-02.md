## 1. Golden result (pure GenesisTopmod, 64v)
`p5_64_taubin5`: V 18,253 / F 36,502, watertight genus 0, **ho16 0.9957**,

## 2. DMesh output resolution is locked by its representation
Every epoch, DMesh starts with the refine-seeded point set and its optimization
prunes >85 % of faces within 500 steps — with the real regularizer at 0 and reals
frozen to 1 every step it is the same (`armadillo_64v_dense_{a,b}.yaml`):

| run | epoch_3 start F | final F | ho16 |
|---|---|---|---|
| default | 15.6k | 4.8k | 0.9891 |
| hires (38k seeds) | 45.6k | 5.5k | 0.9894 |
| dense_a (no real reg, frozen reals) | 45.8k | 8.1k | 0.9889 |
| dense_b (+98k seeds, ud_thresh 1e-2) | **187.7k** | **9.2k** | 0.9885 |

Face existence comes from the weighted-Delaunay tets; denser points compete for
the same faces. More seeds ≠ more output faces. This is the method's ceiling,
not our config.

## 5. Supervision — NOT silhouette-only
Both we and DMesh use GT silhouette + GT depth (256², `W_DEPTH=0.35` + phase-in
ours / `depth_coef 1.0` DMesh) per training view; 64v adds diffuse shading.
DMesh 6v uses our exact 6 cameras (`use_our6`). Only the visual-hull field is
silhouette-only. No `W_DEPTH=0` ablation has been run on armadillo 6v.
Visible-surface error of 0.012 at 6v (vs 0.001 at 64v) means depth is
under-exploited: candidate fix = fuse the 6 depth maps into the hull field (TSDF
style "depth hull") so visible surfaces are pinned by the field.

## 6. Self-intersection lesson (from 09-01/02)
IoU is blind to self-intersections. Boss spotted "too smooth to be ours" →
audit showed 46–83 % SI faces in the reverse-hybrid meshes. Fix that worked:
in-loop DLFL edge flips (delete_edge+insert_edge) + short-edge collapse
(collapse_edge_tri) + SI push every 25 steps: 6v 62 % → 3.4 %, 64v 83 % → 1.6 %.
Collapsing buried faces (3a/3b) and fold-loss ×10 (3c) did NOT work.

## 8. Ablation of the golden chain (2026-09-03)
Steps 2 (extrude carving) and 3 (stand-alone hull pull) are NOT needed: 1-4-5-6 gives 0.9959 / SI 1.5 % /
hair 0 / back 7.3° (golden v1: 0.9957 / 1.4 % / 8 / 7.9°). Step 4 IS needed: subdividing a tangled mesh
multiplies the tangles (1-5-6: 0.9948 but SI 13 %; skip-4 variants 26-33 % SI). The hull field lives inside
the phase-4 loop, which is what made 2 and 3 redundant. Rule: **clean (DLFL flips/collapses) before subdividing.**
IoU alone would have ranked 1-5-6 as "almost golden" — always report SI/folds/dihedral alongside.

## 9. Representation ablation: DLFL vs generic numpy ops (2026-09-03)
Same chain 1(mesh)→4→5→6 with every DLFL call replaced by array-based equivalents (`generic_ops.py`,
`GENERIC_OPS=1`; same rules/guards; Open3D has no per-edge flip/collapse primitives so numpy was used):

| | DLFL (ablation D) | generic |
|---|---|---|
| Step 4 final | 0.9868, SI 2.1 % | (see log) |
| Step 5 final | 0.9915, 36.9k f, SI 4.0 % | 0.9916, 33.0k f, SI 3.0 % |
| Taubin ×5 | **0.9959**, hair 0, back 7.3°, SI 1.5 % | **0.9957**, hair 3, back 6.9°, SI 0.9 % |

Conclusion: the score does NOT come from TopMod. Flip / collapse / subdivide are standard local ops; the
generic version stays watertight (check_watertight asserted every 25 steps) and lands within noise.
Only difference: the DLFL collapse is more conservative (84 vs 201 collapses on the same input), so the
generic chain ends with ~10 % fewer faces. What TopMod provides is manifold closure by construction and
an operator-program record, not accuracy. Paper claim must be phrased accordingly.

## 10. Positioning conclusions (2026-09-03, Boss discussion)
- **Score does not come from TopMod.** Generic numpy flip/collapse/subdivide with the same guards reproduce
  the chain (0.9957 vs 0.9959). TopMod's value = manifold closure by construction (generic version is
  manifold only because every guard was re-implemented by hand: empirical, not structural) + operator program.
- **Guards** = link condition (collapse), "new diagonal not already an edge" + non-degenerate + less-folded
  (flip); subdivision needs none. All textbook; any library can implement them.
- **What only DLFL offers here**: genus-changing manifold ops (`insert_edge` Case B / `add_handle`,
  `delete_edge`). Not used on armadillo (genus 0). Open3D/trimesh/pymeshlab have no such primitive;
  DMesh can change topology but only as a non-manifold soup.
- **DMesh's real advantages**: topology freedom, no initial topology, open/non-manifold surfaces, point-cloud
  recon, slightly better at equal low face count (0.9894 vs 0.9865). Its costs: soup output, resolution
  locked at 5–9k faces, CGAL WDT per step.
- **"No initialization needed" holds only with enough views**: DMesh 6v from random points collapses to
  0.5297; with our manifold mesh as init 0.9705; ours pure 6v 0.9457–0.9555. The closed-manifold
  constraint is a regularizer under sparse views. Trade-off: topology freedom (DMesh) vs manifold prior (ours).
- **Our family** = remeshing-during-inverse-rendering (Palfinger 2022 Continuous Remeshing; Nicolet 2021
  Large Steps). Extras over that line: hull distance field (space carving as loss), clean-before-subdivide,
  Taubin finish, DLFL op set incl. genus ops. Weakness shared with that line: fixed genus — rocker-arm PoC
  (genus 1) is the test of whether hull evidence + add_handle closes this gap.
- Paper baselines to run: DMesh (done), Continuous Remeshing (Palfinger), FlexiCubes/DMTet (grid-based).

## 11. Where we stand (2026-09-04, Boss review)
Self-intersection "measurable and controllable" is NOT a method advantage: DMesh is intersection-free by
construction (WDT faces); Palfinger could add the same Open3D check in a day. It is an engineering property
we report honestly (0-1.4 %), nothing more.

| | DMesh | Palfinger (continuous remeshing) | generic ops (Open3D/numpy) | **ours** |
|---|---|---|---|---|
| manifold output | no (soup) | yes, by construction of the op set | only if every guard is hand-written | **yes, by construction (DLFL)** |
| self-intersections | **zero by construction** | not measured | not measured | measured, 0-1.4 %, not zero |

| resolution | locked 5-9k faces | free | free | free (coarse-to-fine) |

Real, defensible contributions: (1) manifold-guaranteed genus change driven by image evidence;

tunnel below 256^2 resolution, Palfinger baseline still to be run.

## 12. Early-hole experiment + collapse-runaway bug (2026-09-04)
Boss hypothesis: "CC subdivides so many times mainly because of the hole — if we added the hole one
step earlier (on the coarse mesh) we may not need so many CC passes." **Confirmed, once the chain is
fair.** Fair early-hole chain = cc3 -> clean 400 -> add_handle -> **RESUME cc4 + despike (rest of Stage 1)**
-> Stage 4 -> Stage 5 -> AUTO Taubin. The hole is opened on the ~1.8k-face coarse mesh, then the same
cc4 subdivision the normal chain uses is applied afterwards.

| rocker-arm | normal chain (subdivide, then hole) | early-hole v3 (hole at cc3, then cc4) |
|---|---|---|
| faces when hole opened | 5.7k | **1.8k** |
| hole opens clean | 400 steps, hair 495 | 400 steps, hair **495, SI 0 %** |
| final V | 14,501 | 16,743 |
| genus / SI | 1 / 0 % | 1 / **0 %** |
| ho16 | 0.9975 | **0.9979** |

Opening the handle on the coarse mesh is cheaper AND cleaner (SI stays 0 while the ring is small), then
cc4 restores resolution. Earlier v1/v2 scored low (0.994) only because those chains skipped cc4+despike
entirely — that was a chain-construction error, not evidence against the hypothesis.

**Collapse-runaway bug (fixed).** Collapse threshold was "shorter than 50 % of the *current* mean edge".
Each collapse raises the mean edge, so a fresh batch of edges qualifies next pass -> positive feedback
eats the mesh (fertility cc3 1.9k->378 faces genus 8; 3holes final lost 24 % of vertices). Two-layer fix:
(a) `COLLAPSE_FRAC=0.02` caps collapses per pass at 2 % of faces (slows it, not a cure);
(b) `COLLAPSE_ABS`: threshold = `COLLAPSE_RATIO x me0`, where `me0` is the mean edge length computed
**once before the loop**. With the absolute threshold, 3holes finals recovered to genus 3 / ho16 0.9966
with vertex count stable at 10,127 (no more shrinking).

Artifacts: `results_genus/rockerarm_early_auto.npz` (early-hole v3, genus 1, 16,743 V, ho16 0.9979),
`results_genus/threeholes_abs_auto.npz` (genus 3, ho16 0.9966, COLLAPSE_ABS).

## 13. Curvature-adaptive remeshing on DLFL ops (2026-09-04, Boss review of fertility density)
Boss: "why does the head need more vertices but get fewer, and the legs the opposite?" Measured:
GT allocates by detail (density 226 at the base -> 413 at the head); ours was inverted (base 4.4x GT,
head 1.1x). Mechanism: verts migrate into flat/concave regions during the sphere->shape deformation;
uniform cc / SUBDIV_ALL lock the imbalance in; collapse is absolute-threshold; nothing in the chain
allocates by curvature.

`ADAPT_REMESH` (phase4, every COLLAPSE_EVERY steps): per-vertex target edge length
L(v) = me0 * lerp(TMAX=1.6 -> TMIN, smoothstep(dihedral, 8..30 deg)), split faces whose longest edge
> 4/3 L (DLFL subdivide_edge), collapse edges < 4/5 L (DLFL collapse, per-vertex threshold).
Iteration history — every step was a Boss catch:
- v1: Stage-4 adaptive + Stage-5 SUBDIV_ALL -> 138k faces, pure-Python DLFL passes >3 min, timeout.
  Stage-5 is now adaptive-only (SUBDIV_ALL redundant with adaptive growth). ADAPT_MAX_F=60000.
- v2: fertility ho16 0.9960 but SI 39.5 %: **self-intersection jitter reads as curvature** (30-70 deg
  band) -> refined -> more jitter (SI 3.9 % -> 46 %). Fix = "clean before subdividing" in continuous
  form: curvature measured on a Taubin-smoothed copy (ADAPT_SMOOTH_K=3), SI faces + 1-ring never
  split, global gate ADAPT_SI_GATE.
- v3: gate 3 % never opened on fertility (SI floor via collapse/flip/push is ~3.2 %) -> 1,010 V, 0.9545.
  Gate 5 %; the local SI-ring exclusion is the real mechanism.
- v4: 2 px floor on L (ADAPT_LMIN_PX, px = 2*max_radius/256 from the camera setup). fertility fixed:
  **ho16 0.9962 (old chain 0.9885), SI 0.8 %, 12.2k V, density/GT 2.2-3.4x across bands (inversion
  gone)**. rocker-arm 0.9984 but 31.7k V (3.2x GT), mean edge 1.6 px, cap-limited.
- v5: Botsch-Kobbelt 4/3 / 4/5 thresholds. End state unchanged (rocker-arm 31.3k V, 1.6 px, 0.9985;
  fertility 12.3k V, 0.9962): the B-K equilibrium mean is ~0.8 L, so L = 2 px *is* a 1.6 px mesh.
  The floor works; 2 px was the wrong number for "earned" resolution (GT-decimation: 36.5k faces ->
  0.9985; GT rocker-arm itself is 20k faces at 2.8 px).

Open (Boss, 2026-09-04): points went to the LEGS, not the body. Dihedral measures 1/radius, not
detail or fit error: a thin limb is "high curvature" even when already well fitted. Space carving
exists only as a position loss (voting hull, W_T=20) and plays no part in where to refine.
Proposed next: error-driven refinement — split score = per-face silhouette/depth residual over the
64 views (nvdiffrast triangle-id buffer) + hull violation (HF.dist), curvature secondary.

## 14. Residual-driven refinement (2026-09-05, Boss: "points should grow on the body, not the legs")
Dihedral "curvature" = 1/radius: thin limbs are refined even when already fitted. Replaced the
drive with the image-fit error itself (`ADAPT_MODE=residual`): per-face error over the 64 views
(|sil - GT| + W_DEPTH |depth - GT| on covered pixels via the nvdiffrast triangle-id buffer, plus
missing GT-foreground pixels attributed to the nearest rendered face), divided by covered
pixel-views -> absolute, pixel-scale, shape-agnostic. Space carving stays a position loss only.
- v7 (quantile-normalised): placement right (fertility splits 60-70 % mid-body, base 5-20 %) but
  by construction half the mesh is "fitted" -> coarsened: fertility 2.4k V / 6 px / 0.9899.
- v8 (absolute thresholds + KEEP policy: > 0.05/px unfit -> halve local edge; < 0.01/px and flat ->
  may coarsen; else keep current local edge; collapse threshold separated so keep-verts only lose
  slivers): fertility **0.9974**, SI 0.5 %, hair 0, but 18.8k V (4.2x GT) -- the inherited base
  over-density is never coarsened (base residual is not < 0.01).
- v8b (coarsen wherever fitted, R_KEEP 0.02, KEEP_FLAT=0): fertility **0.9969 / SI 0.5 % / 9.4k V
  (2.1x GT) / 2.9 px**; density/GT 2.3 2.4 2.2 1.8 1.7 1.9 (flat, inversion gone).
- Split/collapse caps: uncapped pure-Python DLFL ran 25 min without finishing a pass; 2 %/2 % is
  asymmetric (a split adds ~4 verts, a collapse removes 1) -> linear growth. 5 % / 20 %.

## 15. How others decide where to refine (survey, 2026-09-05) + head-to-head on our loop
| family | signal that sets the local target edge length | needs | source |
|---|---|---|---|
| curvature sizing field | L = sqrt(6 eps/k - 3 eps^2), k = max principal curvature (cot-Laplace H + angle-deficit K), gradation-limited, split > 4/3 L, collapse < 4/5 L; one parameter eps | geometry only | Dunyach 2013 (EG short), Botsch-Kobbelt 2004; CGAL / PMP implementations |
| velocity closed loop | ref_len *= 1 + (nu - nu_ref) gain, nu = per-vertex Adam speed; every iteration; coarser where still moving, finer once settled | optimizer state | Palfinger 2022, Continuous Remeshing (code: core/opt.py) |
| target-normal face score | FS(f) = sum over super-samples projected onto the target of (1 - n_vertex . n_face) | a target surface (SDF / points) -- not available in inverse rendering | ROAR 2023 |
| curvature + uniform, periodic | every 130-200 it: split high-(k1,k2) edges, uniform split elsewhere by mean edge, collapse below min, flips to valence 6, tangential smoothing; genus FIXED from GT via Gauss-Bonnet | GT genus | "Inverse Rendering for High-Genus Surface Meshes", 3DV 2026 (baseline Nicolet; Armadillo IoU 0.928, genus-4 0.885, genus-5 0.750) |
| image importance + flow | attention map modulates split thresholds; "attention flow" propagates importance to neighbours (without it, low-attention regions stay under-refined) | images | SIGGRAPH 2024 poster on Continuous Remeshing |
| image residual (ours) | mean image error per covered pixel-view per face -> halve / keep / coarsen | images | this work (section 14) |
MVS tradition (Vu 2012, facetwise 2020) refines vertices along the photometric gradient with
resolution tied to image pixels; no one in inverse rendering sizes the mesh by the loss residual.
Take-aways: (1) our residual sizing is defensible and closest to the attention-flow poster, whose
lesson is gradation (ADAPT_GRADE); (2) if curvature is kept, use Dunyach with eps in pixels -- one
parameter, tied to supervision; (3) Palfinger's "do not refine what is still moving" is a principled
tangle guard (jitter = motion); (4) the under-refined head is shared by every image-driven method;
(5) 3DV-2026 needs the GT genus, we discover it -- a clear differentiator.
Head-to-head (same DLFL loop, guards, 3 px floor, gradation 1.0, caps 5/20 %; fertility + rocker-arm,
early64v -> Stage-4 -> Stage-5 -> AUTO Taubin): modes curvature | dunyach | velocity | curv_uniform |
residual. Results: see table below (task mode_matrix).
